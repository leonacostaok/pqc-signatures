# SLH-DSA SHA-2 backend ablation

Compare the unchanged original `fd44469daeffe6b28f031f54f9bb66cbae69a572`, the full production candidate `b14f1b616f938698ebc0bf8b75b3736c30e1502c`, and two isolated reduced variants. SHA256-only reverts `sha2_512.c` and the corresponding vendored patch hunk; SHA512-only reverts `sha2_256.c` and its patch hunk. All initialization, configuration/deprecation guards, instrumentation, endian conversions, and secret-state cleanup in the retained path remain identical to the full candidate. The original production checkout and PR patch are unchanged.

The full patch adds 257 lines: 64 in the two runtime hash sources, 6 in CMake/generated-template include handling, 114 reproducing the runtime changes in the vendored-source patch, and 73 in tests/integration. `minimal-runtime.patch` contains the same two runtime changes and the generated CMake include path (three files, 67 added lines). `evidence/minimal-runtime-proof.json` verifies that its three diff sections exactly equal the full patch sections. It is a source-equivalence demonstration, not a separately measured fifth variant or a recommendation to omit maintained tests and importer/template integration.

The unchanged reviewed native driver from `../ten-new-keys/driver.c` is linked against each archive. Original/full reuse their sealed binaries; reduced variants compile that identical driver with identical options. The new corpus uses the separate `pqc-ten-new-keys-v1/liboqs/sha2-ablation-final-v1` derivation domain. Each fresh process generates ten distinct measured keys per SHA2 parameter set, after one disjoint warmup seed per parameter. Messages span 0–8192 bytes and contexts 0–255 bytes. Public native keygen, sign, and verify each run once per key with fresh objects and buffers; allocation, object creation, and validation are outside the timers. The fixed test-process RNG callback supplies identical exact seed/signing entropy bytes in every variant, including their copy cost but excluding operating-system entropy acquisition. There is no production RNG modification or cross-operation decoded-key cache.

Preparation checks both raw SHA-2 compression states and digest padding/truncation edges against the original and independent digests. Every variant receives all four configuration checks (OpenSSL, portable, dlopen fallback, deprecated APIs unavailable), each with 5710 differential checks. A test-only symbol probe distinguishes SHA256-only, SHA512-only, full, and original transform calls and verifies cleanup. Reduced builds also run the upstream private incremental/copy hash test. Complete sixty-key preflight output archives must agree exactly across all four variants before sealing; every timed output archive must match that reference, and every measured signature must verify and reject the selected tampered-signature mutation outside timing. Preflight and final measurement records are separate; each measured process starts fresh after preflight exits.

The final schedule is six rounds comprising three order/reverse-order pairs: original/256/512/full, full/512/256/original, 256/full/original/512, 512/original/full/256, full/original/512/256, 256/512/original/full. Each pair of variants appears in each temporal order three times. Each round launches four fresh processes serially; all rounds retain the complete six-parameter corpus and all losses. No other coordinated benchmark or build runs during the granted window. Host load averages are recorded as diagnostics, not proof of isolation from ordinary desktop work.

Predeclared primary comparison: for each parameter and operation, sum its ten matched-key elapsed times in each variant within each round. Report all six reduced/full ratios, their median and range, and both wall and process CPU results. A median reduced/full ratio no greater than 1.03 is only a practical 3% slowdown screen, not a statistical equivalence claim from six forks. Report the direct latency penalty as `reduced_time/full_time - 1`, and reduced speedup divided by full speedup as `full_time/reduced_time`; the latter is not the fraction of time saved. Original-relative speedups, individual matched-key losses, and every round are retained. Signing and verification are the headline comparisons; key generation is separate. SHA512-only on SHA2-128f/s is an unused-backend control. CPU intervals include the two wall-clock reads.

The runner requires complete correctness reports, source/build/backend hashes, unchanged reference outputs, exact round/variant/key coverage, positive integer wall/CPU times, successful child exits, and immutable output directories. The earlier full experiment's seal is checked throughout. `check_runner.py` demonstrates rejection of missing, duplicate, reordered, failed, or misbound final matrices; the reviewed per-key acceptance checks remain in use. Results are limited to the recorded Apple M1 Pro arm64 host and OpenSSL backend. Larger portability or statistical-equivalence claims require separate evidence.


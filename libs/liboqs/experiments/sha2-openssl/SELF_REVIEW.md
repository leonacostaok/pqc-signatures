# Review of the final liboqs candidate

The production change is limited to the SHA-256 and SHA-512 compression functions and their conditional OpenSSL header dependency. The private SHA-2 interfaces, cached public-seed states, addresses, message framing, padding, signature layout, and RNG path remain unchanged. Eight chaining words are converted from the existing big-endian representation to OpenSSL's host-word state, one message block is transformed, and eight result words are converted back. Differential checks compare the entire state/block storage against portable upstream, including preservation of the input block.

The temporary OpenSSL contexts are fully initialized and explicitly cleansed after result copyback. The cleanup probe checks both calls, the full 328-byte extent, and zero contents; linked optimized arm64 assembly retains the two cleanup calls. All added state is automatic storage, with no new persistent state or runtime dispatch. There is no deterministic RNG hook in production or timed signing.

The default backend and the three fully tested fallback configurations pass their applicable hash and public-signature tests. The standalone test target explicitly receives the selected OpenSSL include directory. The CMake template and importer patch preserve the change on source regeneration, and the complete upstream patch applies cleanly to the pinned official baseline. The baseline and candidate source hashes and benchmark executable hashes differ; only the candidate executable imports both OpenSSL compression transforms. The red/green backend test independently distinguishes those paths.

The complete public API benchmark retains every corpus case and process pair. The root coordinator independently recomputed all 576 raw rows and 12 summaries. Signing includes the production RNG, while verification uses the same valid fixture signatures for both variants. Status and output checks run outside timing. The final snapshot is frozen; later linkage/host-load assessment reports are separate from the raw evidence.

Remaining review limits are explicit: measurements cover this Apple M1 Pro and OpenSSL 3.6.4; the low-level OpenSSL SHA APIs are deprecated and may be a maintainer policy concern; Windows, big-endian, other OpenSSL releases, and full Linux dlopen execution were not tested. The complete macOS dlopen configuration fails in unchanged upstream SONAME discovery. Review corrected an initial NIST exit-zero report that skipped 84 external verification cases. The corrected driver and separate public adapter now pass all 396 NIST and 216 shared cases with execution markers, including fail-closed controls. The sealed legacy script was restored exactly and the corrected driver saved separately. Normal desktop activity remained during final timing and is recorded, with no observations discarded. No additional production correctness defect was identified in this scoped review.

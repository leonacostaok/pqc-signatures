This addendum compares the historical audit at `80c832da6ce81ca8def12b319da9f4c19d589111` with benchmark `origin/main` at `45076e05b67a6792e3bbb5115256e776e790cd1c`. Source and saved JSON were inspected directly with `git show`; no builds, tests, timing runs, or provider edits were performed for this update. Historical runtime reproductions remain evidence about the earlier snapshot; unchanged source supports the current findings but is not a new execution. The only source change under `libs/` or `common/` between these commits is `libs/noble/src/crossverify.mjs`.

The production performance patches and their separate, sealed experiments do not repair the original benchmark harness. In particular, the liboqs SHA2 compression-backend change and OpenSSL SHA512 public-prefix cache operate in upstream library code; neither adds the experimental CIRCL caches, the liboqs stage wrapper, or the common orchestration described below. A successful production-PR experiment does not establish that the historical six-provider report is a reliable final gate. Conversely, these harness findings do not establish defects in the corresponding upstream public APIs.

## Still present

### High: CIRCL ML-DSA prepared-cache identity aliases mutable input

`libs/circl/cmd/pqcbench/stages_ml44.go:57` stores `pk` and `ctx` directly, and `:167` compares future inputs against those same slices before reusing derived key and message-prefix state. Identical code remains at lines 57 and 167 in `stages_ml65.go` and `stages_ml87.go`. The historical reproduction demonstrated acceptance of an original signature after mutating the caller's public-key buffer, while the uncached verifier rejected it. Current source is byte-for-byte unchanged. Likely scope: the reusable experimental `total_best` verifier at all three ML-DSA levels, including context identity by the same aliasing mechanism; fixed immutable benchmark inputs and the upstream public API are not demonstrated affected. Copy identities during initial preparation, as the rebuild path already does at `:176`, or bind the cache to an immutable key/context object. Preserve mutation and alternating-input regression cases. See [JG-1](js-go.md).

### Medium: CIRCL SLH-DSA failed import leaves inconsistent verifier state

`libs/circl/cmd/pqcbench/stages_slh.go:41` replaces `m.pub` before import succeeds; `:42–43` returns on failure without invalidating the existing verifier or saved key identity. `:227–230` subsequently skips rebuilding for the old key. The earlier valid → truncated key → valid sequence produced true, false, false in both stage totals; current source is unchanged. Likely scope: false rejection after a malformed key in a reused experimental stage object, rather than a new upstream acceptance flaw. Build replacement state in temporaries and install it only after success, or invalidate the whole cache on failure. See [JG-2](js-go.md).

### High: liboqs stage setup omits defensive context-bound validation

`libs/liboqs/src/bench.c:755` reserves `pre[2 + 255]`; `:763` calls `make_pre` before checking the context length. That helper at `:316–319` narrows the length to one byte and copies the caller-specified number of bytes. The validation pipeline reaches this setup at `:934`, while ordinary signing and verification reject contexts above 255 bytes at `:324` and `:340`. This constructor is shared by **both ML-DSA and SLH-DSA stage pipelines**, so the historical SLH-focused wording should not imply SLH-only scope. Reject an invalid length at the stage boundary before prefix construction, and propagate a normal verification failure. This remains **static and unreproduced in the complete harness**; no oversized-input probe, memory-safety demonstration, or exploitability claim is made. See [C2](c-providers.md).

### High: missing results and failed final steps can still be reported as success

`common/check-match.mjs:17`, `:31`, `:42`, `:53`, and `:64` still skip missing artifacts; `:55` counts only literal `pass:false`; `:74–77` accepts one stage participant as agreement. It does not read memory verdicts or require an expected coverage matrix. The unchanged checker therefore retains the historically reproduced empty-results success behavior; this update did not rerun that fixture. Require complete expected artifacts, unique case/variant membership, strict verdicts, memory checks, and sufficient stage participants.

`common/run-final.sh:14` still turns a failed command into a successful logging branch, `:32` suppresses checker failure, and `:35` prints `ALL DONE`. `common/run-all.sh:41` likewise suppresses the checker failure. `run-final.sh:12` treats an unbound marker filename as completion and its step graph at `:16–30` still omits vectors and cross-verification. `common/report.mjs:53–55` unconditionally claims a quiet checked run; baseline/leaderboard selection at `:58–61` and `:68` does not require a passing row. Propagate failures, bind resumed steps to inputs/builds/results, and permit final publication only from a complete successful manifest. These are harness acceptance/provenance defects, not evidence that every newly committed result is wrong. See [C1–C4](common.md).

### High: Java validation can select a different measured composition

`libs/bouncycastle/src/Stages.java:481–490` selects and measures a composition, while `:397` later loads `stages.jsonl` under the current-directory-relative default `results/bouncycastle`. `:406–409` silently substitutes defaults when the file is missing, unreadable, or empty. `libs/bouncycastle/run.sh:58` passes the absolute common-input directory but no results path. Validation uses this lookup at `src/Validate.java:111`, and memory at `src/Memory.java:82`. Consequently a non-root working directory or custom stage output can validate a different `total_best` pipeline. Pass the exact stage/composition manifest explicitly, fail when it is unavailable, and record its identity in validation rows. This is Java's measured-path identity issue; Rust's totals instead call the same explicit functions through `src/validate.rs:223–224`, `src/schemes.rs:89–90,183–184`, and `src/stages.rs:303,440`. Do not attribute Java's current-directory lookup defect to Rust. See [RJ-1](rust-java.md).

### High: Java/Rust validation verdicts do not control command success

Java writes and prints failures without failing the process at `libs/bouncycastle/src/Validate.java:78–83`; its child runner merely logs a nonzero exit at `:138–140`. Rust similarly only writes and prints counts at `libs/rustcrypto/src/validate.rs:253–259` and in the merge at `:269–279`, without rejecting missing or duplicate expected rows. The historical deliberately failing Java fixture exited zero; no new execution was attempted here. Preserve diagnostic output, then return failure on any failed case, child failure, or coverage mismatch. Combined with the common checker omissions, partial subprocess results can otherwise appear complete. See [RJ-2](rust-java.md).

### Medium: source identity and stage-work discrepancies remain

Rust's timestamp check at `libs/rustcrypto/run.sh:40–41` still omits vendor sources; `:53` and `:74` can reuse PGO/base binaries after vendor changes, and `:55–58` still labels an unprofiled fallback as a PGO variant. This can make validation and timing refer to stale or differently configured code. Use Cargo dependency tracking plus complete source/toolchain/profile identities.

Java SLH `hmsg` still uses a signature parsed outside its timed closure (`libs/bouncycastle/src/Stages.java:140`, `:224`). Rust ML-DSA decode still serializes the complete decoded structure inside the timed closure (`libs/rustcrypto/src/stages.rs:256–258`) and serializes both sides inside the memory closure (`:312`). liboqs SLH totals still call the full hypertree preparation inside `run_pipeline` (`libs/liboqs/src/bench.c:801–807`) before separately repeating WOTS/authentication work (`libs/liboqs/src/stages_slh.c:62–136`). These are unchanged measurement-boundary problems; canonical digest agreement does not make those isolated stages or totals comparable. See [RJ-4–RJ-5](rust-java.md) and [C1](c-providers.md).

The common generator still lacks public-key length mutations, oversized contexts, and persistent-object mutation sequences (`common/gen-validation.mjs:68–99`). Its empty-message mutation is a rejection case, not successful empty-message signing. Correct existing case results therefore do not resolve the missing boundary and state-transition coverage above.
